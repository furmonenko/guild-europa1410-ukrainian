## Рішення

1. Імена та прізвища транслітеруються кирилицею (правила в `docs/translator-brief.md`).
2. Працюємо в межах підписки Max 5x, без API-ключа. Один захід — не більше ~20% 5-годинного вікна.
3. Літературні розділи перекладає Opus, механічні — Sonnet; рецензує Opus.
4. Жартівливі назви (Name Pools, AmbientBackstories) адаптуємо творчо, але затверджуємо окремо, очима.

## Конвеєр

Усе, що не переклад, робить скрипт. LLM викликається headless (`claude -p`, без інструментів, один хід,
власний системний промпт, structured output), тому фіксовані витрати виклику ≈ 1 тис. токенів.

```
python translate.py terms --translate          # (зроблено) 318 кодів → termcodes.json, переглянути вручну
python translate.py run <ціль/розділ> --model sonnet|opus --effort low|medium --max-cost N
python uk.py check
python translate.py review <ціль/розділ> --model opus --max-cost N
   → переглянути work/review/<ціль>/<розділ>.json, зайве видалити
python translate.py apply <ціль/розділ>
python uk.py install                            # перевірити в грі, зауваження → glossary.md / brief
git commit
```

Що робить `run`:
- пропускає вже перекладене й технічні рядки, перевикористовує переклади ідентичних текстів
  з усіх розділів (translation memory), кожен унікальний текст перекладає один раз;
- сортує за ключем, щоб `_Name`/`_Description`/`_Header` однієї сутності були в одному чанку;
- у промпт додає тільки ті вже перекладені назви (предмети, будівлі…), які трапляються в чанку;
- валідує кожен рядок (розмітка, множина, не англійська, кирилиця), невдалі перезапитує малими чанками;
- зливає результат у `translations/` після кожного чанка, тож зупинка нічого не втрачає;
- `--max-cost` зупиняє захід за сумою `total_cost_usd`; наступний запуск продовжує;
- перший виклик іде сам (прогріває кеш системного промпту), далі паралельно `--workers`.
